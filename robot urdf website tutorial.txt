1. Course Content
Start the 3D state estimation layer and view the car's URDF model in real time in RViz2 using the Orbit 3D view. The model pose is driven in real time by the IMU data of the ESP32 control board — pick up the car and flip or rotate it freely, and the 3D model in RViz2 follows the motion, giving you an intuitive understanding of the coordinate systems of each sensor and the joint structure.

3. Source Code Analysis
3.1 model_display.py
Source code path

$HOME/microros_ws/src/common_demo/common_demo/model_display/model_display.py
model_display.py converts the IMU real-time pose data into TF transforms, so that the URDF model in RViz2 flips and rotates together with the real car.

Node initialization (__init__): Creates a TransformBroadcaster for publishing TF transforms; subscribes to the /imu topic with the qos_profile_sensor_data QoS (IMU usually uses best-effort QoS), with the callback function imu_callback.

IMU callback (imu_callback): After receiving an IMU message, constructs a TransformStamped:

header.frame_id = 'odom', child_frame_id = 'base_footprint', establishing the odom → base_footprint transform chain
The translation is fixed at (0, 0, 0.03), only to keep the model floating at the origin for easy observation of the pose; no position estimation is performed
The rotation quaternion is taken directly from msg.orientation (i.e., the roll/pitch/yaw obtained from IMU fusion), achieving real-time full-pose driving
Calls sendTransform to publish; after receiving the TF, robot_state_publisher automatically computes the poses of all child links (base_link, gimbal, camera, etc.) based on the joint relationships in the URDF
Cooperation with joint_state_publisher: The IMU only drives the overall pose of base_footprint; the cam1/cam2 gimbal joint angles are published separately by joint_state_publisher subscribing to /ptz_status. When the two are combined, the model in RViz2 can simultaneously present the complete effect of the body tilting + the gimbal rotating.


class ModelDisplayNode(Node):
    def __init__(self):
        super().__init__('model_display')
        self.tf_broadcaster = TransformBroadcaster(self)
        # IMU data is usually published with best-effort QoS
        self.imu_sub = self.create_subscription(
            Imu, '/imu', self.imu_callback, qos_profile_sensor_data)
        self.get_logger().info('model_display started: /imu -> tf(odom->base_link)')
​
    def imu_callback(self, msg: Imu):
        t = TransformStamped()
        t.header.stamp = self.get_clock().now().to_msg()
        t.header.frame_id = 'odom'
        t.child_frame_id = 'base_footprint'
        # Translation stays at origin, only attitude is visualized
        t.transform.translation.x = 0.0
        t.transform.translation.y = 0.0
        t.transform.translation.z = 0.03
        t.transform.rotation = msg.orientation
        self.tf_broadcaster.sendTransform(t)

URDF, whose full name is Unified Robot Description Format, is a robot model file described in XML format
Tag Introduction

link, a link, which can be thought of as a human arm

joint, a joint, which can be thought of as a human elbow joint

The relationship between link and joint: two links are connected through a joint. Imagine an arm where the forearm (link) and the upper arm (link) are connected through the elbow joint (joint).

In the URDF description language, link is used to describe physical characteristics:

Describes the visual display, the <visual> tag.

Describes the collision properties, the <collision> tag.

Describes the physical inertia, the <inertial> tag (not commonly used).

origin

Describes the pose information; the xyz attribute describes the coordinate position in the global environment, and the rpy attribute describes its own orientation.

mass

Describes the mass of the link.

inertia

Inertial reference frame. Due to the symmetry of the rotational inertia matrix, only the 6 upper-triangular elements ixx, ixy, ixz, iyy, iyz, izz are needed as attributes.

geometry

The tag describes the shape; the mesh attribute is mainly used to load texture files, and the filename attribute is the file path of the texture.

material

The tag describes the material; the name attribute is required, can be empty, and can be repeated. The rgba attribute in the <color> tag represents red, green, blue, and transparency, separated by spaces. The color range is [0-1].

 

joint describes the relationship between two links, and the motion position and velocity limits, as well as the kinematic and dynamic properties.

Joint types:

fixed: Fixed joint. Motion is not allowed; it serves to connect.
continuous: Continuous joint. Can rotate continuously, without rotation angle limits.
revolute: Revolute joint. Similar to continuous, but with rotation angle limits.
prismatic: Prismatic joint. Moves along an axis, with position limits.
floating: Floating joint. Has six degrees of freedom, 3T3R.
planar: Planar joint. Allows translation or rotation orthogonal to a plane.
In the <joint> tag, the name attribute is required, describing the name of the joint, and it must be unique.
In the <joint> tag, the type attribute corresponds to the six joint types.
